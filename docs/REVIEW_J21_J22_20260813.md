## 1. What the journals are for

J21's goal (from README + docstring): measure the rolled-up mass and surface
area of every BoM-visible 3D master in an open NX 2506 assembly and persist
`NX_MassPropRollupMass` (kg) / `NX_MassPropRollupArea` (mm^2) on each part,
reporting what NX wrote (read-back), with DRY_RUN / SMOKE / PROBE modes.

J22 is a fast one-part diagnostic: on the active work part it tests (A) the
classic measure APIs, (B) the native mass-properties builder, (C) direct
attribute writes per category, and dumps before/after attributes — to decide
which write mechanism works on this NX build.

## 2. The technical story the evidence tells (important)

The commit history and logs show two full direction changes:

1. **Direct-write approach (abandoned).** `docs/NX2506_J21_J22_RESERVED_LOG.md`
   documents an APPLY run of the older V4 build: 15/15 parts
   `WRITE_FAILED` with **"This is a reserved attribute title. [512006]"** for
   both `NX_MassPropRollupMass` and `NX_MassPropRollupArea` in both
   "Rolled-Up Mass Properties" and "Materials" categories. The journal's
   AttributePropertiesBuilder writes were rejected by NX — these titles are
   reserved and only NX's own mass-properties update may populate them.

2. **Native update approach (current, correct direction).** `bc2f4cb` reverted
   J21 to drive NX's native mass-properties update
   (`PropertiesManager.CreateMassPropertiesBuilder` with
   `UpdateOnSave=Yes`, then `UpdateNow` + `Commit`) instead of writing
   attributes directly. The current docstring documents exactly why. This is
   the right mechanism — confirmed independently by J22's diagnostic:
   `C_direct_write` fails with [512006] on every category, while
   `B_native_builder` runs OK.

**So the current J21 direction is technically sound** — it stopped trying to
write reserved attributes and instead triggers the mechanism NX itself uses.

## 4. What is good

- **Correct mechanism decision:** after evidence (reserved-title errors), the
  journals correctly stopped direct-writing reserved attributes and moved to
  the native builder. J22's category testing (Rolled-Up Mass Properties vs
  Materials) is exactly the right experiment.
- **Honest evidence:** the logs report BLANK/PARTIAL rather than fabricating
  success; the JSON dump is a faithful before/after attribute landscape.
- **Self-contained deployment:** no third-party deps, Desktop-based IO with
  `NX_JOURNALS_IO_DIR` override, safe `_text`/`clean`/`error_text` helpers.
- **Tests:** 15 unit tests pass (`pytest tests/ -q` → 15 passed), covering
  APPLY/SMOKE/DRY_RUN/PROBE modes, BOM-visibility filtering, blank
  reporting, save-failure continuation, and a source-level guard
  (`test_native_only_no_manual_compute_or_attribute_write`) that the journal
  does not call `NewFaceProperties`/`NewMassProperties`/
  `CreateAttributePropertiesBuilder`/`SetRealAttribute` — i.e. it enforces
  the native-only contract.
- **Defensive traversal:** suppression/reference/keyword filtering mirrors
  NXOpenBoMExtended; manager fallback (PropertiesManager → MeasureManager)
  and instance-resolved UpdateOptions handle build differences.
